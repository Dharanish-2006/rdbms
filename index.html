PART A — (10 × 2 = 20 marks) · Answer any TEN

1. Define a weak entity. An entity whose existence depends on another (owner) entity and which has no primary key of its own. Example: LOAN depends on CUSTOMER.

2. Differentiate super key and candidate key. A super key is any set of attributes that uniquely identifies a row (may have extra attributes). A candidate key is a minimal super key.

3. What is referential integrity? A foreign key value must either be NULL or match an existing primary key value in the referenced table, e.g. STUDENT.BRANCH_CODE must exist in BRANCH.

4. Define QBE. Query By Example is a graphical, form-based query language where the user fills example values in table skeletons instead of writing SQL; it is related to domain relational calculus.

5. What is normalization? The process of organizing tables into smaller related tables to reduce redundancy and remove insertion, deletion and update anomalies.

6. Define a transaction. A logical unit of work made of one or more operations (read, write) that moves the database from one consistent state to another.

7. Write the difference between UNION and UNION ALL. UNION removes duplicate rows from the combined result; UNION ALL keeps all duplicates.

8. What is a natural join? A join that automatically matches columns with the same name and data type in both tables and shows the common column once.

9. Write the syntax of the CREATE TABLE command. CREATE TABLE Students (ID INT PRIMARY KEY, Name VARCHAR(50));

10. What do ANY and ALL do? > ANY is true if the value exceeds at least one value of the subquery; > ALL is true only if it exceeds every value.

11. Define a PL/SQL procedure. A named PL/SQL block stored in the database that performs a specific task; it may take IN, OUT and IN OUT parameters.

12. What is an exception in PL/SQL? A runtime error condition handled in the EXCEPTION section, e.g. NO_DATA_FOUND, ZERO_DIVIDE.

13. Explain the 3-tier architecture of DBMS.

In 3-tier architecture an application server sits between client and database, so the client cannot talk to the database directly.

  • Presentation tier: user interface running on the client (browser/app).
  • Application (business) tier: processes requests and business rules, and communicates with the database.
  • Database tier: stores data and does query processing and transaction management.

Used in large web applications; it gives better security, scalability and maintenance. In contrast, 1-tier lets the user work directly on the DBMS, and 2-tier lets client programs connect directly to the server through ODBC/JDBC.

5 marks

14. Explain the ISA relationship and its constraints.

Enhanced ER uses superclass/subclass relationships. ISA means “is a”: the lower-level entity (e.g. Hourly_Emps) is a subgroup of the higher-level entity (Employees) and inherits all attributes and relationships (ssn, name, lot).

Constraints:

  • Disjoint: an entity can belong to only one subclass (postgraduate or undergraduate).
  • Overlap: an entity may belong to several subclasses (Frog is both land and water animal).
  • Total participation: every superclass entity must be in at least one subclass (double line).
  • Partial participation: it may be in none (single line).
5 marks

15. Explain the different types of keys.

Keys uniquely identify rows and link tables. Consider STUDENT(STUD_NO, SNAME, ADDRESS, PHONE).

  • Super key: any attribute set that identifies a row, e.g. {STUD_NO, SNAME}.
  • Candidate key: minimal super key, e.g. STUD_NO.
  • Primary key: the candidate key chosen by the designer; unique and never NULL.
  • Alternate key: a candidate key not chosen as primary.
  • Foreign key: an attribute that refers to the primary key of another table (BRANCH_CODE in STUDENT).
  • Composite key: two or more columns together, e.g. {STUD_NO, COURSE_NO}.
  • Unique key: ensures distinct values but permits one NULL.

Keys ensure uniqueness, data integrity, relationships between tables and faster searching.

5 marks

16. Explain the basic relational algebra operations.

Relational algebra is a procedural query language; each operator takes relations and gives a relation.

  • Select (σ): chooses tuples satisfying a predicate. σBRANCH_NAME="Perryride"(LOAN) returns loans L-15 and L-16.
  • Project (∏): chooses columns. ∏NAME, CITY(CUSTOMER).
  • Union (R ∪ S): tuples in R or S, duplicates removed; both must have the same number of attributes.
  • Intersection (R ∩ S): tuples in both.
  • Set difference (R − S): tuples in R but not in S.
  • Cartesian product (R × S): every row of R combined with every row of S (3 × 3 rows gives 9 rows).
  • Rename (ρ): renames a relation, ρ(STUDENT1, STUDENT).
  • Join (⋈): combines related tuples on a condition; natural, equi and outer joins are variants.
5 marks

17. Explain ACID properties of a transaction.

  • Atomicity: all operations happen or none do. If the transfer of Rs 100 from A to B fails after debiting A, it is rolled back.
  • Consistency: integrity constraints hold before and after. A=600, B=300 (total 900); after transfer A=500, B=400, total still 900.
  • Isolation: a data item in use by one transaction cannot be used by another until it finishes; enforced by the concurrency control subsystem.
  • Durability: once committed, changes are permanent even after system failure; handled by the recovery subsystem.

States: Active → Partially committed → Committed; on error → Failed → Aborted (rollback).

18. Explain relational set operators with examples.

Set operators combine the results of two SELECT statements; both need the same number of columns with compatible types.

Table ATable B
1Alice2Bob
2Bob3Charlie
SELECT name FROM A UNION      SELECT name FROM B;  -- Alice, Bob, Charlie
SELECT name FROM A UNION ALL  SELECT name FROM B;  -- Alice, Bob, Bob, Charlie
SELECT name FROM A INTERSECT  SELECT name FROM B;  -- Bob
SELECT name FROM A MINUS      SELECT name FROM B;  -- Alice  (EXCEPT in SQL Server/PostgreSQL)

MySQL lacks INTERSECT/MINUS in older versions; Oracle supports both.

19. Explain cursors in PL/SQL with an example.

A cursor is a pointer to the result set of a query, used to process rows one by one. Implicit cursors are created automatically by Oracle for DML; explicit cursors are declared by the programmer (DECLARE, OPEN, FETCH, CLOSE). Attributes: %FOUND, %NOTFOUND, %ROWCOUNT, %ISOPEN.

DECLARE
  CURSOR c_emp IS SELECT name, salary FROM employee;
  v_name employee.name%TYPE;  v_sal employee.salary%TYPE;
BEGIN
  OPEN c_emp;
  LOOP
    FETCH c_emp INTO v_name, v_sal;
    EXIT WHEN c_emp%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(v_name || ' ' || v_sal);
  END LOOP;
  CLOSE c_emp;
END;
/

20. Explain the building blocks of the ER model and conversion of an ER diagram to tables. Mention its advantages.

The ER model (Peter Chen, 1976) is a high-level conceptual model showing data elements and their relationships as an ER diagram.

Building blocks

  • Entity (rectangle): object, person or place; strong (independent), weak (dependent, double rectangle) or associative.
  • Attribute (ellipse): property of an entity. Key (underlined), composite (made of parts, e.g. address), multivalued (double ellipse, e.g. phone numbers), derived (dashed, e.g. age from date of birth).
  • Relationship (diamond): association between entities; cardinality is 1:1, 1:N, N:1 or M:N; degree is unary, binary, ternary or N-ary.

Reduction of ER diagram to tables

  1. Each entity type becomes a table; each single-valued attribute becomes a column.
  2. The key attribute becomes the primary key.
  3. Derived attributes are not stored.
  4. A multivalued attribute gets a separate table with the owner key, e.g. EMP_SKILL(Emp_ID, Skill).
  5. A composite attribute is represented by its simple components (Street, City, State, Zip).
  6. 1:N relationship: put the primary key of the “1” side as a foreign key in the “N” table.
  7. M:N relationship: create a new table holding both primary keys.
STUDENT(Roll_No PK, Name)      COURSE(Course_Id PK, Title)
ENROLLS(Roll_No FK, Course_Id FK, PRIMARY KEY(Roll_No, Course_Id))

Advantages

  • Easily understood pictorial map for database design.
  • Represents real-world problems well.
  • Straightforward conversion to the relational model.
  • Enhanced ER adds flexibility (ISA, aggregation).
  • Simple, easy-to-follow symbols.

21. Explain Codd’s rules.

Dr. E. F. Codd proposed in 1985 a set of rules (numbered 0 to 12, called Codd’s 12 rules) that a database must obey to be a true RDBMS.

  1. Foundation rule: the system must manage the database entirely through its relational capabilities.
  2. Information rule: all information is stored as values in cells of tables (rows and columns).
  3. Guaranteed access rule: every atomic value is reachable by table name, primary key value and column name.
  4. Systematic treatment of NULL: NULL represents missing or inapplicable data, distinct from zero or blank; primary key cannot be NULL.
  5. Active online catalog: the data dictionary is stored as tables and is queried with the same language.
  6. Comprehensive data sublanguage: at least one language (SQL) supports data definition, views, manipulation, integrity constraints, authorization and transaction control.
  7. View updating rule: all theoretically updatable views must be updatable by the system.
  8. High-level insert, update, delete: operations work on sets of rows, and union, intersection and minus are supported.
  9. Physical data independence: changes in storage or access methods do not affect applications.
  10. Logical data independence: changes to table structure (splitting or joining tables) do not affect user views.
  11. Integrity independence: integrity constraints are stored in the catalog, not in application programs.
  12. Distribution independence: the data may be distributed over locations, yet users see it as one site.
  13. Non-subversion rule: a low-level language cannot bypass the integrity rules expressed in the relational language.

Most commercial RDBMSs (Oracle, MySQL, SQL Server) follow these rules only partially; Codd’s rules serve as the benchmark for a “fully relational” system.

22. Explain normalization with 1NF, 2NF, 3NF and BCNF.

Normalization organizes data into smaller linked tables to minimise redundancy and remove anomalies. Insertion anomaly: cannot insert data without other data. Deletion anomaly: deleting a row loses unrelated facts. Update anomaly: one change must be made in many rows, leading to inconsistency. Functional dependency X → Y means X (determinant) determines Y.

1NF – atomic values

No multivalued cells, no duplicate rows. EMPLOYEE(14, John, "7272826385, 9064738238") is split into one row per phone:

EMP_IDEMP_NAMEEMP_PHONE
14John7272826385
14John9064738238

2NF – no partial dependency

1NF + every non-key attribute depends on the whole key. TEACHER(TEACHER_ID, SUBJECT, TEACHER_AGE) has key {TEACHER_ID, SUBJECT} but TEACHER_ID → TEACHER_AGE is partial. Decompose:

TEACHER_DETAIL(TEACHER_ID, TEACHER_AGE)    TEACHER_SUBJECT(TEACHER_ID, SUBJECT)

3NF – no transitive dependency

2NF + for every non-trivial FD X → Y, X is a super key or Y is a prime attribute. In STUDENT(enrol_no, name, dept, building_no): enrol_no → dept and dept → building_no, so enrol_no → building_no is transitive. Decompose:

STUDENT(enrol_no, name, dept)       DEPARTMENT(dept, building_no)

BCNF – every determinant is a super key

EMPLOYEE(EMP_ID, EMP_COUNTRY, EMP_DEPT, DEPT_TYPE, EMP_DEPT_NO) with FDs EMP_ID → EMP_COUNTRY and EMP_DEPT → {DEPT_TYPE, EMP_DEPT_NO}; candidate key {EMP_ID, EMP_DEPT}. Neither determinant is a key, so decompose:

EMP_COUNTRY(EMP_ID, EMP_COUNTRY)
EMP_DEPT(EMP_DEPT, DEPT_TYPE, EMP_DEPT_NO)
EMP_DEPT_MAPPING(EMP_ID, EMP_DEPT)

Now the left side of every FD is a key, so each table is in BCNF.

Advantages: less redundancy, consistency, flexible design. Disadvantages: more joins and possibly slower queries, careless decomposition can harm design.

23. Explain SQL joins (inner, outer, cross, natural, USING, ON) with examples.

A join combines rows of two or more tables based on a related column.

StudentsMarks
1Ram185
2Sita290
3Ravi470

1. INNER JOIN / JOIN ON

SELECT * FROM Students s INNER JOIN Marks m ON s.ID = m.ID;

Only matching rows: Ram 85, Sita 90. Ravi and ID 4 are excluded. ON allows different column names and any condition.

2. LEFT OUTER JOIN

SELECT * FROM Students LEFT OUTER JOIN Marks ON Students.ID = Marks.ID;

All students; Ravi appears with Score NULL.

3. RIGHT OUTER JOIN

All rows from Marks; the mark for ID 4 appears with Name NULL.

4. FULL OUTER JOIN

All rows from both tables, NULL where no match: Ram, Sita, Ravi (NULL) and ID 4 (NULL name).

5. CROSS JOIN

SELECT * FROM A CROSS JOIN B;

Cartesian product: 2 rows × 2 rows gives 4 rows (Ram-HR, Ram-IT, Sita-HR, Sita-IT). No condition is used.

6. NATURAL JOIN

SELECT * FROM A NATURAL JOIN B;

Joins automatically on all same-named columns, which appear once in the output.

7. JOIN USING

SELECT name, dept_name FROM employees JOIN departments USING (dept_id);

Used when the column has the same name in both tables; no table prefix is allowed on that column afterwards. Result: Alice HR, Bob Marketing.

8. SELF JOIN

SELECT A.Name, B.Name FROM Employees A, Employees B WHERE A.ManagerID = B.EmpID;

A table joined with itself. Equi join uses “=”, non-equi join uses >, <, !=.

24. Explain PL/SQL: block structure, control structures, exception handling, procedures, functions and triggers.

PL/SQL is Oracle’s procedural extension of SQL combining SQL with variables, conditions, loops and error handling.

Block structure

DECLARE   -- optional: variables, constants, cursors
BEGIN     -- mandatory: executable statements
EXCEPTION -- optional: error handling
END;
/

Control structures

IF marks >= 90 THEN grade := 'A';          -- conditional
ELSIF marks >= 75 THEN grade := 'B';
ELSE grade := 'C'; END IF;

FOR i IN 1..5 LOOP DBMS_OUTPUT.PUT_LINE(i); END LOOP;   -- iterative
WHILE counter <= 5 LOOP counter := counter + 1; END LOOP;

Three kinds: conditional (IF, CASE), iterative (LOOP, WHILE, FOR with EXIT, CONTINUE) and sequential (default order, GOTO, NULL).

Exception handling

BEGIN
  SELECT salary INTO v_salary FROM employee WHERE emp_id = 100;
EXCEPTION
  WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('Employee not found');
  WHEN TOO_MANY_ROWS THEN DBMS_OUTPUT.PUT_LINE('More than one employee');
  WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('Error occurred');
END;

User-defined exceptions are declared (e_age EXCEPTION;) and raised with RAISE.

Procedure and function

CREATE OR REPLACE PROCEDURE show_salary(p_salary NUMBER) IS
BEGIN DBMS_OUTPUT.PUT_LINE('Salary = ' || p_salary); END;
/
CREATE OR REPLACE FUNCTION square_num(n NUMBER) RETURN NUMBER IS
BEGIN RETURN n * n; END;
/

A procedure performs an action and is called as a statement; a function must return a value and can be used in expressions. Parameter modes: IN, OUT, IN OUT.

Trigger

A stored program that fires automatically on INSERT, UPDATE or DELETE. Timing: BEFORE, AFTER, INSTEAD OF; level: statement or row (FOR EACH ROW, using :OLD and :NEW).

CREATE OR REPLACE TRIGGER salary_check
BEFORE UPDATE OF salary ON employee FOR EACH ROW
BEGIN
  IF :NEW.salary < :OLD.salary THEN
    RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be reduced');
  END IF;
END;
/

Packages group related procedures, functions and variables in a specification and a body, giving modularity and reuse.
